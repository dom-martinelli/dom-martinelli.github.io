question

Can a browser app read a child's growth history straight from a health record and surface faltering a short visit would miss?

calls made
  • growth engine fenced off during the feature build. the percentile tables, interpolation and anomaly rules were the part already checked.
  • demo cases built around trajectory, velocity and delayed recognition, not population-specific expected growth. a subgroup-specific chart can make a remediable problem look typical.
  • model API key asked for at run time and held in sessionStorage. the app ships as static files, so anything in the repo ships with it.
  • self-hosted HAPI added as the custom-data lane, Epic kept as the interoperability lane. only the read source changes; the growth logic does not.
what broke
  • first scopes requested were user-level, which return no patient context. switched to patient-level and printed the granted scopes to debug it.
  • the sandbox patient came back with no vitals at all, so the chart had nothing to draw. synthetic measurements added as a fallback.
  • the plain category search for vital signs did not work; the query needs the full terminology system URI, and requests need an explicit FHIR JSON Accept header.
  • switching between demo patients and plotting the parental target line were both wrong after the feature build.
what i tried

dropped the Epic OAuth launch in the follow-on build for a HAPI server with a patient dropdown, because the teaching vignettes had to be ones I could author and load myself.

not shown
  • percentiles come from a small embedded boys-only table, interpolated, not a validated LMS engine
